# Semantic workflow evaluation subset

For ASTRA engineers testing interpretation boundaries and deterministic workflows. All examples are synthetic. Labels are engineering hypotheses for team review, not private teacher data or measured model results.

The initial subset contains 153 semantic/paraphrase records, 21 multi-turn scenarios (28 turns), and 23 structural/admission/safety cases. Development and evaluation partitions are grouped by scenario family, and the harness checks IDs and family leakage. Neither partition was used to expand production phrase matching. The approximately 700-record coverage objective remains open; do not inflate these counts with duplicated templates.

`semantic-corpus.jsonl` records Vietnamese input, context, dialogue act, ordered goals/slots, constraints and prohibited goals. `workflow-scenarios.json` records initial state and expected clarification, catalog selection or bounded recipe outputs. `adversarial-corpus.json` contains malformed contracts, unsupported/ambiguous dialogue, input limits and whole-turn constraints. `catalog.fixture.json` is a snapshot of this checkout's authoritative catalog. Native transport fixture data is generated by `scripts/export_semantic_contract.py`; do not hand-edit it.

Run from the repository root:

```powershell
node --experimental-strip-types astra-frontend/scripts/evaluate-semantics.mjs --output eval/agent-semantic/offline-results.json
```

This validates oracle frames and deterministic resolutions. It never performs inference or business operations. The local fast-path match rate is coverage, not routing accuracy. The p50/p95 timing measures local parsing/resolution only, excluding model, HTTP and rendering time. Model metrics remain null without predictions.

To score a separately authorized saved run:

```powershell
node --experimental-strip-types astra-frontend/scripts/evaluate-semantics.mjs --predictions runs/authorized-predictions.jsonl --output runs/model-evaluation.json
```

Each prediction has `id` and `frame`. Keep real private prompts/output out of Git. The harness reports goal accuracy, exact ordered goal-and-slot accuracy, dialogue-act accuracy, schema failure, out-of-scope recall and false executable proposals on supplied evaluation records. It does not execute those proposals or claim zero unauthorized execution in production. Missing predictions are reported through the evaluated coverage count, rather than scored as successful.

Native request/response failures and persistent quota concurrency are executed by the focused Python/workerd tests. Actual React handlers and confirmations are covered by the two mounted browser scripts. Their evidence is separate from language-understanding accuracy and live provider acceptance.

## Local routing and generation recovery extension (2026-11-28)

`local-routing.json` adds144 authored utterances across34 paraphrase families (68 development,76 evaluation) and12 authoritative job-selection contexts. This supplements the existing153 semantic records; it does not relabel them. Families stay in one partition. Coverage includes current catalog subjects, lifecycle commands, progress/reasons, recovery lists, Word/Markdown, history, existing navigation/question editing/memory, unsafe/ambiguous requests and deliberate model fallbacks. No real exam, teacher content or inference is used.

Run `node --experimental-strip-types astra-frontend/scripts/agent-benchmark.mjs --save` from the root. The compatibility entry point now uses the grouped evaluator instead of the old16 manually entered examples. It temporarily loads the original recipes from commit98b1df5 for an explicit local-routing comparison; it removes that scratch module afterward. `local-catalog.fixture.json` is generated offline from `exam_baseline.ui.contracts.format_catalog()` (eight actual available formats), rather than invented subjects. Live application selection always fetches the real catalog.

The generated `local-routing-results.json` records semantic conformance, coverage, false execution on safety cases, incorrect accepted fast paths, model-fallback counts, context selection and4,320 warmed routing timings. A `safe` label checks **only absence of an executable proposal**, accepting clarification or model fallback; it is excluded from the separate semantic-case count. Counts of avoided model fallbacks are a counterfactual routing proxy, not observed API traffic or cost savings. Timing excludes HTTP, rendering, RAG and inference.

Evaluation is authored and visible to the engineer, not an independent blind study. The first evaluation exposed a mixed note-plus-approval fast path. That safety bug was fixed and the case retained as regression; reported evaluation metrics are **post-fix**. Keep this caveat when citing the numbers. No fixture result measures Gemini accuracy or live exam quality. New independently authored families are still desirable before making generalization claims.
