## Reused Backend and protocol

Academic configuration remains Settings / EXAM_* in [config.py](../../src/exam_baseline/config.py). The new provider=worker_mas selects [WorkerMasProvider](../../src/exam_baseline/providers/worker_mas.py), a small subclass of the existing [ChatCompletionsProvider](../../src/exam_baseline/providers/chat_completions.py). It replaces only URL/authentication headers. The existing payload builder, schema/tool options, optional image encoding, spend accounting and Completion/usage/error parser remain authoritative. Native UI JobManager passes its HTTP client into that adapter. Baseline service startup uses the same explicit provider selection; no direct-provider fallback is selected.

Path: existing THPT/V-ACT agents → ordinary Chat Completions JSON → MAS Worker /v1/chat/completions → fixed Gateway google-ai-studio/v1beta/openai/chat/completions → ordinary provider envelope → existing Backend parser/academic validation. No Agent Chat schema, academic prompt rewrite or second orchestration system. Agent classes, question schemas, RAG, formats, scoring, revision/repair policy, answer checks, human approval and rendering are unchanged.

Google documents the /v1beta/openai/ Chat Completions protocol and structured responses. Cloudflare documents the Google provider base and provider-specific passthrough paths. The implemented URL combines those documented pieces; actual acceptance of this path with this stored credential still needs the approved real job. No live compatibility result is inferred from unit fixtures. Sources: [Google OpenAI compatibility](https://ai.google.dev/gemini-api/docs/openai), [Cloudflare Google provider](https://developers.cloudflare.com/ai-gateway/usage/providers/google-ai-studio/).

The Worker attaches cf-aig-authorization and cf-aig-byok-alias internally and omits provider Authorization/x-goog-api-key so the stored BYOK key can be used. This follows [Cloudflare BYOK authentication and alias handling](https://developers.cloudflare.com/ai-gateway/configuration/bring-your-own-keys/). It sets no-wholesale, max-attempts=1, no-cache and no payload logging. The Backend's existing bounded transport/schema retries remain; all admitted attempts consume the MAS allowance.

## Access and limits

Internal test access uses one random 256-bit bearer credential, stored as encrypted ASTRA_MAS_CALLER_TOKEN on the Worker and only in ignored `.env.mas-worker` locally. It is a revocable Worker access token, not a Gemini key or Gateway Token. No frontend bundle/config receives it. A stage name grants no access. Missing/wrong token and browser Origin are rejected before admission; no CORS proxy is exposed. To revoke, disable forwarding or replace this Secret and update the ignored local caller profile through a secure local workflow. Never paste its value into chat, logs or Git.

Independent MAS_ADMISSION Durable Object / mas-global-v1, migration v1-mas-admission, preserves lifetime used/estimated-token counters and daily history across restarts/UTC rollover. Reservations are transactional; failed upstream calls are never refunded. Successful/known-failed requests release capacity; uncertain timeout/cancellation leases expire naturally. This namespace does not share counters or capacity with Chat. Lifetime allowance does not renew on UTC rollover. A future allowance extension must preserve used counters.

Current academic output cap 8192, upstream deadline 90 seconds, local HTTP timeout 100 seconds to allow proxy overhead, concurrency 3 for existing V-ACT concurrency. Request bound 1 MiB, response 2 MiB; allowed model is exactly the configured MAS model. Streaming, arbitrary destinations/provider credentials, extra outputs and caller model overrides are rejected. Versioned hard bounds are in workers/astra-mas-proxy/src/limits.json; these are MAS limits, not Chat's 1024-token/30-second limits. Structural logs contain request ID, valid role/stage, status, timing and numeric usage only; successful response JSON is passed unchanged to the Backend.
