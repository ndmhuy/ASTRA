## Scope & Exclusions (from `De-thi-minh-hoa-2026-dgnl.pdf`)

- **Excluded (pages 1–4):** Cover page, `LỜI MỞ ĐẦU`, `MỤC LỤC`, and `HƯỚNG DẪN LÀM BÀI THI` are booklet front matter, not part of a generated exam contract.
- **No extra fields needed (page 5):** The exam header (`ĐẠI HỌC QUỐC GIA THÀNH PHỐ HỒ CHÍ MINH / KỲ THI ĐÁNH GIÁ NĂNG LỰC`) and `CẤU TRÚC ĐỀ THI` summary table are already baked into `PROTO_vact_vact.tex` for PDF preview, and the web UI can render them from existing `ExamFormat` / `blueprint` metadata (`title`, `durationMinutes`, `totalQuestions`, `sections`).
- **Included (pages 6–22):** 5 sections, 120 four-choice MCQs (`q1`–`q120`), 3 English sub-instruction blocks (`31–35`, `36–40`, `41–45`), and 21 shared passage/scenario/table groups (`g21_25`–`g118_120`).

## 2. Generate & Evaluate Request (`POST /api/exam-formats/evaluate`, `POST /api/exams/generate`)

Minimal V-ACT variant alongside the existing THPT `GenerateRequest` (discriminated by `formatId`):

```json
{
  "formatId": "vact",
  "formatVersion": "1",
  "subject": "Tổng hợp",
  "grade": 12,
  "examType": "DGNL_DHQG",
  "durationMinutes": 150,
  "itemCount": 120,
  "prompt": "",
  "uploadedFiles": [],
  "slots": null
}
```

- `slots: null` resolves to the default 120-slot template matrix (`examples/vact/request.json`, `q1`–`q120` across the 12 template batches).
- Custom `slots`, if supplied, must pass `exam_baseline.vact.models.Request` validation (exact 120 slots matching `q1`–`q120` and batch IDs).
- `prompt` (optional, max 10,000 chars) maps to `vact.models.Request.requirements` (`[prompt]` when non-empty).

## 3. Live UI Render Contract (`GET /api/exams/{job_id}` & PDF Preview)

### PDF Preview (`ExamPreviewState`) — No Changes Needed
- `POST /api/exams/{job_id}/preview`, `GET /api/exams/{job_id}/preview`, `preview.pdf`, `preview.log`, and `ExamPreviewState` work unchanged because `PreviewService` compiles the job's `de_thi.tex` generated by `vact.orchestrator.Orchestrator` (`font_profile="unicode_times"`).
- Note on V-ACT visuals: `vact.rendering.render()` renders `Passage.table` as LaTeX `tabular` and `Question.illustration_request` via TikZ `Drawings` on the linked `Question` (including grouped data/chart questions such as `q97`–`q99`).

### Live Paper / Review Payload (`ExamPackage` + `QuestionItem`)
Minimal backward-compatible additions to `astra-frontend/src/types/exam.ts` and `JobManager.package()` (all new fields optional so THPT responses remain valid unchanged):

```ts
export interface ExamPassageTable {
  columns: string[];
  rows: string[][];
}

export interface ExamPassage {
  id: string; // e.g. "g21_25", "g97_99" (from vact.models.Passage.id)
  section: 'TV' | 'TA' | 'TO' | 'LOGIC' | 'SCIENCE';
  kind:
    | 'passage'
    | 'vact_passage_en'
    | 'math_context'
    | 'logic_puzzle'
    | 'data_set'
    | 'science';
  questionRange: [number, number];
  instruction: string;
  heading?: string;
  text: string;
  table?: ExamPassageTable | null;
}

// Minimal changes to existing types:
// 1. ExamPackage.totalScore: number | null
// 2. ExamPackage.passages?: ExamPassage[]
// 3. QuestionItem.part?: string   (THPT: 'P1'|'P2'|'P3'; V-ACT: 'TV'|'TA'|'TO'|'LOGIC'|'SCIENCE')
// 4. QuestionItem.passageId?: string | null
// 5. QuestionItem.groupInstruction?: string
```

#### Minimal Frontend Rendering Notes (`ExamPaperView.tsx` & `QuestionCard.tsx`)
- Render section headers from format metadata (`sections[]`) rather than hardcoding `P1`/`P2`/`P3`.
- When rendering questions in order, look up `passages.find(p => p.id === q.passageId)` and render the passage card (`instruction`, `heading`, `text`, structured `<table>`) once before the first question in that group; similarly render `q.groupInstruction` once when it changes (`q31`, `q36`, `q41`).
- In `QuestionCard.tsx`, display `Câu {index + 1}.` (or strip `"q"` from `stableId` when non-hyphenated, since `stableId` is `"q1"`–`"q120"` rather than `"P1-1"`).
- `drawingLatex` stays a source preview hint in HTML while `Xem trước PDF` remains the canonical TikZ/LaTeX view.

1. **`totalScore` value:** Use `null` (recommended — official V-ACT uses IRT scaling rather than linear point sums) vs `1200` placeholder?
2. **Phase 1 route scope:** Ship V-ACT **generate + live Paper/Review/PDF preview + approve/export** first, and defer per-question/passage `PUT /questions/{id}` and `POST /questions/{id}/regenerate` to a follow-up?
3. **`QuestionItem.part` granularity:** Confirm using the 5 section IDs (`TV`, `TA`, `TO`, `LOGIC`, `SCIENCE`) rather than the 12 internal Composer batch IDs (`TV_1_10`, `TV_11_20`, etc.).
